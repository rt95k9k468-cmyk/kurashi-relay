# 中継所

ショートカットが健康データを置き、くらしノートが受け取る、小さな郵便受けです。

これを立てると、毎朝の手順が

> ショートカットを走らせる → アプリに戻る → 「コピーしたものを取り込む」を押す

から

> （オートメーションが勝手に走る）→ アプリを開けば、もう入っている

になります。押すボタンが無くなります。アプリは、**見えているあいだ静かに
覗き続けます**——画面がどれであっても、です（前はダイエットと daily が
出ているときだけでした）。

---

## なぜ外を一周させるのか

iPhone の中だけでデータを渡す道は、このアプリの形（Webアプリ）では全部ふさがっています。

| 方法 | 使えるか | 理由 |
|---|---|---|
| URLスキーム（`kurashi://…`） | ✕ | ネイティブアプリの仕組み。Webアプリは名乗れません |
| ユニバーサルリンク | ✕ | 同上。受け取るのはネイティブアプリだけです |
| Web Share Target | ✕ | Safari が実装していません（WebKit bug 194593、いまも open） |
| ショートカットから URL を開く（`?health=…`） | △ | **開くのは Safari のほう**です。ホーム画面のアプリと Safari は保存領域が別なので、入れたデータはホーム画面側から見えません |
| クリップボード | △ | いまの方法。ホーム画面のアプリからは `readText()` が断られるので、毎回「ペースト」を押す必要があります |
| **中継所（これ）** | ○ | 端末の外を一周するので、保存領域の分断を越えられます |

つまり「渡す」のではなく「置いておいて、取りに行く」形にします。

## 何を置くのか

置くのは**手入力とまったく同じ文字**です。

```
day=2026-08-17
steps=8432
sleep=7:12
```

くらしノート側は、受け取った文字列を手入力・貼り付けと**同じ読み取り処理**に渡すだけです。増えるのは入口であって、読み方ではありません。だから中継所は中身を一切見ません。

## どこにあるか

このリポジトリの **`relay/`** です。

```
rt95k9k468-cmyk/kaimono-note      （公開・ブランチ main）
└── relay/
    ├── wrangler.jsonc        設計図（KVは id を書かない＝作らせる）
    ├── worker.js             中継所の本体
    ├── .dev.vars.example     配置のときに RELAY_PATH を尋ねさせるため
    ├── package.json
    ├── worker.test.mjs       ふるまいのテスト（外に出ません）
    ├── embed.js              worker.js をアプリに埋め込み直す
    ├── setup.sh / verify.sh  パソコンがある場合の道具
    └── README.md             これ
```

**GitHubからそのまま配置できる構成にしてあります。** 貼り付けも、KVを手で
作って結ぶ作業も要りません。仕掛けは二つだけです。

- `wrangler.jsonc` の `kv_namespaces` に **`id` を書いていない** → Cloudflare が
  「まだ無いので作る」と解釈して置き場を用意し、id を書き戻します
- `.dev.vars.example` に `RELAY_PATH=` がある → 配置の途中で
  **Secret として尋ねられます**

## 建て方（iPhoneだけ・パソコン不要）

**手順はぜんぶ、アプリの中にあります。** 設定 → ダイエット → **中継所** を開いて
ください。①〜④の順に並んでいて、難しいところは全部ボタンになっています。
ここに書くのはその控えです。

### ① 道（合言葉）をつくる

アプリの **「道をつくる」** を押します。`/kn-…` が出て、クリップボードに乗ります。

iPhoneに `openssl` はありませんし、人が思いつく「適当な文字列」は適当では
ありません（誕生日や名前が混ざります）。だからアプリが作ります——紛らわしい
四文字（`l 1 o 0`）を落とした32文字から16文字ぶん、80ビットです。

### ② 中継所を置く（コピペ不要）

アプリの **「Cloudflareに置く」** を押すと、この `relay/` を指した配置画面が
開きます。

1. Cloudflareに登録（メールアドレスだけ。カードは要りません）
2. GitHubとつなぐ画面が出たら許可する
3. **RELAY_PATH** を聞かれたら、①でコピーした道を**ペースト**
4. **Deploy**

押すと、コードも置き場（KV）も Cloudflare が用意します。

ボタンの行き先はこれです（手で開くなら）:

```
https://deploy.workers.cloudflare.com/?url=https://github.com/rt95k9k468-cmyk/kaimono-note/tree/main/relay
```

**RELAY_PATH を聞かれなかったら**、置いたあとに
**Settings → Variables and Secrets → Add** で、Type を **Secret**、名前を
`RELAY_PATH` にして置いてください（それから **Deploy**）。

**うまくいかないときは、Cloudflareの画面からも同じことができます。**
**Create** → **Import a repository** → `kaimono-note` を選び、
**Root directory** に `relay` と入れて配置します。**あなた自身のリポジトリ**なので、
GitHubをつなげば一覧に出ます。置き場（KV）が自動で用意されなかったときだけ、
**Storage & Databases → KV** で作って、**Settings → Bindings** で `MAIL` という
名前に結んでください。

> **コードを手で貼るやり方は、iPhoneでは勧めません。** 編集画面（Edit code）は
> パソコン向けの部品でできていて、指での「すべてを選択 → ペースト」がうまく
> 効かないことがあります。上の二つは、どちらも貼り付けを必要としません。

### ③ URLをつなげる

Cloudflareの Worker の画面に出ている `…workers.dev` をコピーして、アプリの
**WorkerのURL** の欄に貼り、**「道をつなげる」** を押します。①で作った道が
後ろに付きます。**手で打ち継ぐ必要はありません。**

### ④ 確かめる

アプリの **「中継所を確かめる」** を押すと、その場で一往復して

```
✓ 置けた
✓ 置いたものがそのまま取れた
✓ 渡したら消えた
✓ 道が違えば渡さない
```

を確かめます。通らなければ、**どこで止まったかと、何を直せばいいか**が出ます
（`RELAY_PATH` が無い、KVが結ばれていない、道が違う…）。

確かめる前に郵便受けを空にするので、もう届いていたデータは**捨てずに取り込みます**。

最後に **保存** を押してください。

## ショートカットを直す

いまのショートカットの**最後の「クリップボードにコピー」だけ**を差し替えます。前の部分（ヘルスサンプルを検索 → 統計を計算 → テキスト）はそのままです。

1. 「クリップボードにコピー」を削除
2. **「URLの内容を取得」**を追加
3. URL に中継所のURLを入れる
4. その行の **▸（矢印）を開いて**：
   - **方法**：`POST`
   - **本文を要求**：`ファイル`
   - **ファイル**：一つ前の「テキスト」の結果を差し込む

> 「本文を要求」を `JSON` のままにすると、`{"key":"value"}` の形で送られてしまいます。`ファイル` にすると、テキストがそのまま本文になります。

5. 走らせて、**ダイエットタブを開く**。トーストに「中継所：…」と出れば成功です。

## 睡眠のステージを送る（別のショートカット）

歩数などとは別に、**睡眠の四つの型（深い・コア・レム・覚醒）**を送れます。
こちらは統計を計算せず、**ヘルスケアが返す区間をそのまま**送ります。

1. **ヘルスサンプルを探す**
   - 種類：**睡眠分析**
   - 絞り込み：**開始日** が **前日の12:00** より後（「過去36時間」でも構いません）
   - 並び替え・上限：なし（一晩ぶんで50〜90件、7KBほどです）
2. **繰り返し**（各項目に対して）→ **テキスト** に次の一行を作る

   ```
   {"duration":"（時間）","value":"（値）","end":"（終了日）","start":"（開始日）"}
   ```

   ショートカットの「ヘルスサンプル」の変数から、それぞれを差し込みます。
3. **テキストを結合**（区切り：**改行**）
4. **URLの内容を取得** → 方法 `POST`、本文を要求 `ファイル`、ファイル＝③の結果

アプリ側は `duration` を**読みません**（`"12:29"` は12分29秒で、`sleep=7:12`
の「7時間12分」と同じ形なのに意味が違うため）。`start` と `end` の差から
数えるので、`duration` は空でも構いません。

### いつ走らせるか

**起きる時刻より確実にあとに。** まだ寝ている最中に走ると、**その時刻が
起床時刻として記録されます**（エラーは出ません）。

休みの日に遅くまで寝るなら、**9時・10時・11時・12時**のように何回か
仕掛けておくのが安全です。同じ晩について**遅く終わる読みが来たときだけ**
書き替えるので、何度届いても悪くなりません。早い便で切れた記録は、
あとの便で自動的に直ります。

## 読めなかったときは、送らない（いちばん大事な一手）

**iPhoneがロックされているあいだ、ヘルスケアのデータは読めません。**
暗号化されたままなので、無人で走るオートメーションはそこに当たります。

困るのはそのあとです。ショートカットの「統計を計算 → 合計」は、
**0件のとき 0 を返します**。つまり中継所には

```
steps=0
activeEnergy=0
sleep=0
```

が置かれます。くらしノートはこれを**入れません**（0 で塗り替えないため）。
ただし郵便受けのほうでは、**この空振りが、まだ読まれていない良い便を
差し替えて**しまいます。一時間おきに仕掛けていても、画面の数字が数時間前の
ままだったのは、これがいちばん大きな理由でした。

中継所は「ひとつ前の便」も一緒に渡すようになったので、一回ぶんの空振りなら
耐えます。それでも、**空振りを送らないのがいちばん確かです**。

### 直し方（一手だけ）

「ヘルスサンプルを検索」のすぐ下に、二つ足します。

1. **数える**（Count）→ 項目 → 入力は「ヘルスサンプル」
2. **もし** 〈数〉 が **0 に等しい** なら → **このショートカットを停止**

これだけです。読めなかった回は何も置かれず、郵便受けには**前の良い便が
そのまま残ります**。

> **「歩数の合計が 0 より大きくなければ停止」でも構いません**が、こちらは
> 日付が変わった直後（本当にまだ一歩も歩いていない時間帯）にも止まります。
> 数えるほうは「読めたか」だけを見るので、より正確です。

### ついでに、時刻も書いておく

テキストに一行足しておくと、くらしノートが「この数字は何時時点か」を
より正確に言えます（無くても取り込んだ時刻で代用します）。

```
time=（現在の日時をフォーマット、HH:mm）
```

### どこに入るか

| | 行き先 |
|---|---|
| 睡眠時間（深い+コア+レム） | ダイエット →「今日のからだ」の睡眠 |
| 起床時刻 | daily → その日の Daily Log |
| 就寝時刻 | daily → **寝はじめた日**の Daily Log（前日とは限りません） |
| 四つの型 | daily の月の書き出し（JSON）に、各日の `sleepStages` として |

手で打った起床・就寝時刻は、取り込みが上書きしません（体重と同じ決めごとです）。

### 勝手に走らせる（何度も）

ショートカットアプリの **オートメーション** → 新規 → トリガを選び →
作ったショートカットを選び、**「実行前に尋ねる」をオフ**。

**iOSの「時刻」トリガは、繰り返しが 毎日／毎週／毎月 の三つしかありません。**
「1時間おき」は作れないので、その頻度が欲しければ**時刻ごとに一つずつ**
仕掛けることになります（7時・8時・9時…）。

そして**時刻のオートメーションには弱点があります**——鳴った瞬間に iPhone が
ロックされていれば、ヘルスケアは読めません。上の「読めなかったときは、
送らない」を入れてあれば害はありませんが、**その回は何も届きません**。

だから、**人が iPhone を触っている瞬間に鳴るトリガ**を混ぜるのが効きます。
触っている＝ロックが解けている＝読める、なので、空振りしません。

| トリガ | いつ鳴るか |
|---|---|
| **アプリ**（が開かれたとき） | **複数のアプリを選べます。** 普段よく開くもの（メール・地図・カメラなど）を何本か選んでおくと、一日に何度も、必ずロックの解けた状態で鳴ります |
| 充電器 | 接続したとき／外したとき |
| Wi‑Fi | 自宅や職場に着いたとき |
| 集中モード | オン／オフの切り替わり |
| アラーム | 止めたとき（朝いちばんに一回） |
| ワークアウト | 終わったとき（歩数が大きく動いた直後） |

> **ホーム画面の「くらしノート」は、「アプリ」トリガの一覧には出ません。**
> ホーム画面のWebアプリはiOSからはアプリとして扱われないためです（実機で
> 確認済み）。だから「くらしノートを開いたら取りに行く」は、この道では
> 作れません。かわりに**アプリの中に口があります**——次の節。

### アプリから、その場で走らせる

くらしノートの **設定 → ダイエット → 中継所 → ⑤** に、ショートカットの
名前を入れておいてください。

すると、ダイエットの「からだ」の見出しの右に出ている **「◯:◯◯ 時点」を
押したときに、そのショートカットがその場で走ります**。指が触れている＝
ロックが解けているので、**空振りしません**。走り終えたら指でくらしノートへ
戻れば、2分間・5秒おきに待ち受けているアプリが拾います。

「古いな」と思ったその場で最新にできる、いちばん短い道です。

## ショートカットを二本以上にするとき

**そのまま二本走らせて大丈夫です。** 中継所は差出人ごとに一通ずつしまい、
アプリが取りに来たときにまとめて渡します。

はじめは郵便受けが一つしかありませんでした。ショートカットが一本のうちは
足りていましたが、二本目（睡眠）を足した時点で壊れます——「からだ」を置いた
上に「睡眠」を置くと、からだのほうが読まれないまま消えます。一時間ごとに
両方が走れば、アプリが取りに来たとき残っているのは最後の一通だけ。
「たまに4件まとめて入る」「ふだんは更新されない」はこれでした。

差出人の見分け方は、本文の一文字目です。`{` か `[` で始まれば「JSON の便」
（睡眠のような生の記録）、それ以外は「テキストの便」（`key=value` の書式）。
中身は読みません。一文字だけ見ます。

三本目からは、URL の末尾に `?slot=名前` を付けて名乗ってください。

```
https://…workers.dev/kn-…?slot=weight
```

同じ差出人の新しい便は、その差出人の前の便を差し替えます。だから一時間ごとに
同じ睡眠を置いても溜まりません（残るのは一通）。

> **worker を入れ替える必要があります。** 仕切りも、版も、ひとつ前を残すのも
> 中継所側の仕掛けなので、アプリだけ新しくしても効きません。アプリの
> 「中継所のコードをコピー」から貼り直すか、`kurashi-relay` の `worker.js` を
> 差し替えてください。入れ替えたとき郵便受けに残っていた便は、捨てずに
> 一緒に渡します（古い形の控えも読めるようにしてあります）。
>
> 入れ替えたかどうかは、アプリの **④ 中継所を確かめる** の一行目で分かります。

## Siri から買うものに足す（受け箱）

「Hey Siri、買うものに追加」→「何を？」→「牛乳」で、くらしノートの
買うものに牛乳が入ります。健康データと同じ道（ショートカット → 中継所 →
アプリ）を通るので、Safari のほうのくらしノートに入ってしまうことはありません。

**置き先**は、中継所のURLの末尾に `?slot=add` を付けたものです。アプリの
**設定 → ダイエット → 中継所 → Siri 用のURLをコピー** で、そのままコピーできます。

**ショートカットの組み方**（新しく一本）：

1. **入力を要求**（種類：テキスト、質問：「何を買いますか？」）
   ——Siri から走らせると、Siri が声で聞いて、声で受け取ります
2. **URLの内容を取得**
   - **URL**：Siri 用のURL（`…/kn-…?slot=add`）
   - **方法**：`POST`
   - **本文を要求**：`ファイル`
   - **ファイル**：①の「入力」
3. （好みで）**テキストを読み上げる**：「入れました」
4. ショートカットの名前を **「買うものに追加」** にする——この名前がそのまま
   Siri への呼びかけになります

言い方の決まり：

- いくつかなら **「牛乳、卵」** のように区切ってください（読点・中黒・改行）。
  「と」では切りません——「とうもろこし」が割れるので。
- 「牛乳を追加」「卵も買って」のように頼みの言葉まで言っても、名前だけが入ります。
- もうリストに載っている（済ませていない）品物は、二つめを足しません。
- 棚（カテゴリ）は、手で足すときと同じ振り分けで決まります。

**アプリに入るのは、アプリが見えているとき**です（中継所を覗くのは見えている
あいだだけ）。閉じているあいだに足したぶんは、次に開いたときにまとめて入り、
「Siri から買うものに「牛乳」を入れました」と出ます。設定の「自動で取り込む」を
切ってあると、ダイエットの「◯:◯◯ 時点」を押したときにだけ入ります。

**受け箱だけは差し替えずに溜めます。** 健康データは新しい一通が古い一通を
含んでいますが、買うものは一通ずつが別の頼みなので、差し替えると三つ目で
一つ目が消えます。一通ごとに置いた時刻（必ず前より大きい数）を添えて溜め、
アプリはどこまで足したかをその数で覚えるので、何度渡されても二度足しません。
消すのは一週間経ったものだけです。

> **worker を入れ替える必要があります**（2026年9月27日の版から）。古い
> worker に `?slot=add` で置くと、ふつうの棚と同じく差し替えられて、三つ目で
> 一つ目が消えます。入れ替えたかどうかは **中継所を確かめる** で分かります
> ——受け箱が無ければ、結果の終わりにそう出ます。
>
> 厳密に言うと：Cloudflare の配置画面（②）から GitHub とつないで置いた場合は、
> `main` が新しくなったときに Cloudflare が作り直すことがあります（つなぎ方に
> よります）。確かめるのがいちばん早いです。

## 閉じていても鳴らす（やることの時刻）

アプリを閉じていても、やることの時刻に iPhone が鳴るようにできます
（2026年9月27日の版から）。中継所が毎分、時刻の列を見て、来たものだけ
iPhone へ押します。

**中継所が知るのは時刻だけです。** 渡るのは「いつ鳴らすか」の数の列と、
押し先（iPhone の通知の宛先）だけ。やることの題もメモも渡りません。
通知に出る題は、iPhone の中に写しておいたものから出ます。

**入れ方**：くらしノートの 設定 → やること →「やることの時刻を知らせる」を
入れる → すぐ下の **「閉じていても鳴らす」** を入れる。中継所をつないで
いないと、この行は出ません。

- **worker を入れ替える必要があります。** 古い中継所だと「中継所のコードが
  古いため入れられません」と出ます。
- **毎分の見回り（Cron）が要ります。** Cloudflare に置く ボタン（②）や
  Import a repository で置いた人は、設計図（`wrangler.jsonc` の `triggers`）が
  足します。**コードを手で貼った人は**、Worker の画面の
  **Settings → Triggers → Cron Triggers → Add** で `* * * * *`（毎分）を
  足してください。足していないと、入れても鳴りません（エラーも出ません）。
- 送るのは**今日から7日先まで**。アプリを開くたび・やることを変えるたびに
  送り直すので、**7日開かないと鳴らなくなります**。
- 押しは中身なし（何も書かれていない合図）です。**iPhone で本当に鳴るかは、
  実機で確かめてください**——鳴らなければ教えてください（合図を暗号にして
  載せる形に切り替えます）。
- 無料枠：毎分の見回りは KV の読み1回（1日1,440回。上限は10万回）。書くのは
  時刻の列が変わったときと、鳴らしたときだけです。
- 切るときは、同じ行を切れば中継所の列と押し先が片づきます。

## 気にしておくこと

- **URLが鍵です。** 人に見せるスクリーンショットに写り込ませないでください。漏れたと思ったら、アプリで新しい道を作り、Cloudflare の **Settings → Variables and Secrets** で `RELAY_PATH` を差し替えて **Deploy**、アプリの設定も入れ直します（それだけで古いURLは死にます）。
- **中身は暗号化されません。** 通信は HTTPS ですが、中継所の中では平文です。置かれるのは歩数・睡眠・体重といった数字で、名前も端末IDも含みません。それでも他人のサーバに置きたくないなら、自分のサーバに同じことをする10行を置いても構いません（POSTで保存、GETで返して削除、CORSを許す、それだけです）。
- **取っても消えません。** かわりに「いちばん新しい便を置いた時刻」を版として返し、変わっていなければ空の返事（204）をします。だから何度覗いてもタダで、取りこぼしも二度取り込みも起きません。端末を替えても、最後の便はまだそこにあります。捨てたいときは `DELETE` を投げてください（アプリの「中継所を確かめる」は、試した便を自分で片づけます）。
- **ひとつ前の便も残ります。** 差し替えるとき、前の一通を下ろして取っておきます。GET は「ひとつ前 → いま」の順に渡すので、いまの便が空振り（ロック中の 0 の羅列）でも、前の良い便が残ります。
- **置いた直後は、まだ届いていないことがあります。** KV は結果整合で、置いたことが世界中に伝わるまで最大60秒ほどかかります。ショートカットを走らせた**直後**にタブを開くと空のことがあるので、そのときは一度タブを離れて戻ってください。毎朝のオートメーションで走らせるぶんには、まず起きません。
- **同じ便が二度渡ることが、稀にあります。** 置いたことの伝わり方が結果整合だからです。アプリ側は同じ日の同じ種類を差し替えるうえ、一度通した便は覚えていて落とすので、二度入っても記録は増えません。
- **一週間で捨てます。** 取りに来ないまま溜め続けても意味がないので。
- **無料枠。** 一時間おきに置いて、アプリが数分おきに覗いても届きません。置くのは一日48回ほど（KVへの書き込みは1回につき3つ、合わせて150ほど。上限は1000/日）、覗くのはアプリが見えているあいだだけで、新しい便が無ければ**読み込みすら起きません**（版だけ見て 204 を返します）。Workers の10万リクエスト/日にも遠く届きません。

## 壊れていないもの

中継所は**入口が一つ増えるだけ**です。

- 手入力（取り込みシートの①の欄）— そのまま
- コピーしたものを取り込む — そのまま
- ファイルから取り込む — そのまま

中継所を設定していないアプリは、これまでと完全に同じ動きをします。
